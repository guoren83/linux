Build CONFIG_64BIT kernel-self with ILP32 ABI

Since 2001, the CONFIG_64BIT kernel has been built with the LP64 ABI,
but this patchset allows the CONFIG_64BIT kernel to use an ILP32 ABI
for construction to reduce cache & memory footprint (Decreased about
20% used memory in "free -h" under rv64ilp32 abi kernel v.s. lp64 abi
kernel).

Caution, this patchset doesn't introduce any new userspace ABI; only
kernel-self!

The patchset targets RISC-V and is built on the RV64ILP32 ABI, which
was introduced into RISC-V's psABI in January 2025 [1]. This
patchset equips an rv64ilp32 kernel with all the functionalities of
a traditional 64-bit kernel, yet restricts the address space to 2GiB.
So, the rv64ilp32 abi kernel supports lp64 and ilp32 (compat) abi
userspace, which is the same as the traditional lp64 abi kernel.

  +--------------------------------+
  | +------------+---------------+ |
  | |            |   (compat)    | |
  | |  lp64-abi  |   ilp32 abi   | | User
  | +------------+---------------+ |
  +--------------------------------+-------
  | +----------------------------+ |
  | |  lp64 abi  / rv64ilp32 abi | | Kernel
  | |              ^^^^^^^^^^^^^ | |
  | +----------------------------+ |
  +--------------------------------+-------
  | +----------------------------+ |
  | |  rv64gcbvh (RISC-V 64-bit) | | ISA
  | +----------------------------+ |
  +--------------------------------+

This patchset is now in its third version. The major update is the shift
to CONFIG_64BIT with u64lp64 & u32ilp32 abi support. The prior versions
(v1, v2) are all based on CONFIG_32BIT and only support the u32ilp32
abi.

The innovation of v3 lies in supporting lp64-abi userspace rootfs by
inheriting CONFIG_64BIT.


Motivation
==========
Because all RISC-V RVA(B) Profiles are based on the 64-bit ISA, the market
has experienced a significant rise in RISC-V 64-bit ISA SoCs or CPU cores
for resource-constrained scenarios:

 - allwinner/sun20i-d1-lichee
 - allwinner/sun20i-d1s-mangopi
 - canaan/k230d
 - microchip/mpfs-beaglev-fire
 - renesas/rzfive-smarc
 - sophgo/cv1800b
 - sophgo/cv1812h
 - sophgo/sg2002

The listed RV64 ISA-based SoCs with limited memory (less than 1GiB) can
benefit from this patchset. The benefits are decreasing memory footprint
and improving performance due to increased cache density.


Demo Introduction
=================
To test this patchset, you need a toolchain. The rv64ilp32 ABI is integrated
as a feature within the standard rv64 toolchain. We've provided an RV64
multi-lib toolchain [2] that integrates QEMU & rootfs binaries for a quick
start.

After download:
$ tar zxvf riscv64-elf-ubuntu-22.04-gcc-nightly-*-nightly.tar.gz
$ cd riscv/qemu-linux
 - Image_rv64ilp32		rv64ilp32 abi linux kernel
 - Image_rv64lp64		lp64  abi linux kernel
 - u64lp64_rootfs.ext2		lp64  abi user rootfs
 - fw_dynamic.bin		opensbi firmware
 - start-qemu-rv64.sh		qemu cmd script wrapper

Quick start:
$ ./start-qemu-rv64.sh Image_rv64ilp32 u64lp64_rootfs.ext2
v.s.
$ ./start-qemu-rv64.sh Image_rv64lp64  u64lp64_rootfs.ext2


Used Memory Comparison
======================
Under the same configuration, the used memory decreased by 20% with the
rv64ilp32 ABI kernel replacement (Qemu, firmware, and lp64 rootfs are
the same, with their md5sums matching).

./start-qemu-rv64.sh ../Image_rv64ilp32 ../rootfs.ext2.64lp64
$ free -h
       total  used   free  shared  buff/cache   available

              ^^^^

./start-qemu-rv64.sh ../Image_rv64lp64  ../rootfs.ext2.64lp64
$ free -h
       total  used   free  shared  buff/cache   available

$ cat start-qemu-rv64.sh
exec qemu-system-riscv64 -cpu rv64 -M virt -m 128m -nographic -bios ../fw_dynamic.bin -kernel $1 -drive file=$2,format=raw,id=hd0 -device virtio-blk-device,drive=hd0 -append "rootwait root=/dev/vda ro console=ttyS0 earlycon=sbi norandmaps no5lvl no4lvl"

.config Difference
==================
The patchset adds CONFIG_ABI_RV64ILP32 to Kconfig, switching the
compile options from "-mabi=lp64 -melf64lriscv" to
"-mabi=ilp32 -melf32lriscv" depending on CONFIG_64BIT. So, The
differences of Kconfig between with and without ABI_RV64ILP32
are rare:

 - CONFIG_PAGE_OFFSET		0xc0000000.
 - CONFIG_ILLEGAL_POINTER_VALUE	0x0.
 - CONFIG_ABI_RV64ILP32: 	Compile option depends on CONFIG_64BIT.
 - CONFIG_HAVE_CMPXCHG_DOUBLE:	The rv64ilp32 kernel offers new feature.
 - CONFIG_ZONE_DMA32:		It's unnecessary for rv64ilp32 kernel.
 - CONFIG_CSD_LOCK_WAIT_DEBUG	Because of BITS_PER_LONG = 32, rv64ilp32
				doesn't support.
